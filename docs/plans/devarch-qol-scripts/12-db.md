# Phase 12: Database helper

Created: 2026-08-19
Purpose: Replace memorized container names and client flags with explicit, database-aware operations.

## Goal

Add `scripts/devarch/db.sh` for safe connection, inspection, dump, restore, create, and reset workflows.

## Scope

- Initial adapters: MariaDB/MySQL, PostgreSQL, MongoDB, Redis, and SQLite where tied to an app.
- Commands: `list`, `shell`, `query`, `dump`, `restore`, `create`, and `reset` with adapter-specific validation.
- Resolve shared service or app-owned database identities explicitly.
- Reuse backup manifest/dump primitives from phase 08 rather than forking formats.
- Require stdin/file inputs and avoid exposing passwords in command arguments.

## Outputs

- Database helper, adapters, tests, and command examples.

## Acceptance criteria

- `list` is read-only and explains supported operations per database type.
- Interactive shells preserve TTY behavior; noninteractive query mode preserves stdout and exit codes.
- Create/reset/restore are dry-runnable and require explicit confirmation; reset takes a safety dump by default.
- Identifiers are adapter-quoted or strictly validated and cannot inject queries.
- Credentials are delivered through supported environment/stdin mechanisms and redacted.

## Verification

- Recording-client tests verify exact argv/environment boundaries and identifier rejection.
- Fixture tests cover missing clients, stopped containers, query failures, TTY/non-TTY, and safety dump failure.
- Optional disposable round-trip smoke tests run per adapter.

## Non-goals

No GUI, schema migrations, cross-engine conversion, arbitrary production connection profiles, or SQL query builder.
