# Phase 12: Database helper

Created: 2026-08-19
Purpose: Replace memorized container names and client flags with explicit, database-aware operations.

## Goal

Add a database target resolver that invokes the vendor's native CLI through `podman exec`; do not create a database-management API.

## Scope

- Resolve shared service or app-owned database identity, container, database name, and documented credential source.
- Provide `shell TARGET -- NATIVE_ARGS...` and narrowly documented dump/restore recipes for MariaDB/MySQL, PostgreSQL, MongoDB, Redis, and SQLite.
- Invoke `mariadb`, `mariadb-dump`, `psql`, `pg_dump`, `pg_restore`, `mongosh`, `mongodump`, `mongorestore`, `redis-cli`, or `sqlite3` through `podman exec` (or a documented client container) with native args unchanged.
- Prefer users typing native SQL/admin commands in the native shell over implementing `create`/`reset` verbs. Add a guarded helper only where DevArch has a concrete naming invariant and cannot express it safely as a documented native command.
- Require stdin/file inputs and avoid exposing passwords in command arguments.

## Native delegation

Database vendors own parsing, quoting, output, interactive behavior, dumps, restores, and compatibility. Podman owns process/TTY execution. DevArch resolves the local target and credentials only.

## Outputs

- Thin target resolver, vendor-native command mappings, recording tests, and direct command examples.

## Acceptance criteria

- `list` is static/read-only and prints the exact recommended native command for each target.
- Interactive shells preserve TTY behavior; noninteractive query mode preserves stdout and exit codes.
- Restore or any retained DevArch-specific reset helper requires confirmation; native tools retain their own flags/prompts and a safety dump is a separate explicit native operation.
- DevArch-generated identifiers are strictly validated; arbitrary SQL is never generated from user input.
- Credentials are delivered through supported environment/stdin mechanisms and redacted.

## Verification

- Recording-client tests verify exact `podman exec` and vendor-CLI argv/environment/stdin boundaries and identifier rejection.
- Fixture tests cover missing clients, stopped containers, query failures, TTY/non-TTY, and safety dump failure.
- Optional disposable round-trip smoke tests run per vendor-native command mapping.

## Non-goals

No database API, SQL generator/query builder, output parser, GUI, schema migration layer, cross-engine conversion, or arbitrary production connection profiles.
