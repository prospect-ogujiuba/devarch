## Goal

Migrate the entire current service catalog to complete reviewed metadata and close real policy violations without cargo-cult changes.

## Observable behavior

- Every tracked `services-library/**/compose.y*ml` directory has valid local metadata and a declared config-level or runtime smoke assertion.
- All 190 current service entries are classified for health/readiness; the 21 known no-healthcheck entries either gain a meaningful check or carry a reviewed, expiring exception appropriate to aggregate stacks or one-shot jobs.
- A catalog inventory report proves zero missing, orphaned, duplicate, or stale manifests.

## Scope and non-goals

### Scope

- Add one concise `conformance.yml` per current service directory.
- Use generation only for initial mechanical fields; manually review ports, variables, readiness, probes, and exceptions.
- Fix Compose defects discovered by validation only when behavior and compatibility are verified; otherwise record a bounded exception.

### Non-goals

- Do not claim runtime success from config-only validation.
- Do not normalize unrelated Compose formatting.
- Do not replace application-native health semantics.

## Dependencies and entry inputs

- Dependencies: `P02-C01`.
- Entry inputs: active spec, repository baseline, current helpers/tests/READMEs, and all completed dependency outputs.
- Capabilities: Bash, Python 3, Node where already required; runtime contracts additionally require rootless Podman and its configured Compose provider.

## Expected files/outputs

- `services-library/*/*/conformance.yml`
- `targeted services-library/*/*/compose.yml only for verified defects`
- `migration inventory report generated by verifier (runtime artifact, not committed bulky output)`
- `scripts/devarch/tests conformance completeness fixtures`

## Specialist decisions incorporated

- Migration: category-by-category rollout, mechanical generation plus manual review, zero unrelated formatting, reversible metadata-only commits where possible.
- Operations: classify the 21 currently absent health checks instead of applying a blanket health check.
- Security: secret scan and placeholder-only fixtures gate completion.

## Acceptance criteria

1. 100% of tracked service directories pass schema, path, resolved-Compose, policy, and smoke-declaration checks.
2. Every exception names a rule, rationale, owner, and future review date; no blanket or indefinite waiver passes.
3. Diff review confirms no credential values were committed and no unrelated Compose normalization occurred.
4. Adding a fixture service without metadata/smoke fails the local verifier.

## Verification

- Red: repository-wide completeness fails before migration.
- Migrate category-by-category and rerun focused inventory after each category.
- Final: unified static/unit scopes, full resolved-Compose pass, secret scan, and tracked-file completeness check.

## Rollback / migration constraints

Metadata is additive and may be removed by category; targeted Compose fixes revert independently. Keep verifier disabled from CI until full migration passes.
