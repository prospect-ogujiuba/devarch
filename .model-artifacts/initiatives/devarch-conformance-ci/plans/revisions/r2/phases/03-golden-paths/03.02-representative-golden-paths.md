## Goal

Implement four secret-free clean-checkout scenarios that prove DevArch’s representative user journeys at external boundaries.

## Observable behavior

- WordPress provisions a base site without private plugins, proves HTTP content and database readiness, and removes the site/database/runtime resources.
- Laravel provisions the bare SQLite path or an isolated MariaDB path, proves migration state and wildcard-proxy HTTP using a Host header, and cleans up.
- A pinned lightweight JavaScript profile scaffolds and starts through the isolated Node runtime/router, proving HTTP and one API/static boundary without hosts-file mutation.
- A database + application + proxy composition proves service discovery, database query/write-read, and wildcard routing as one integrated path.

## Scope and non-goals

### Scope

- Add declarative scenario definitions and thin scenario-specific assertions.
- Introduce only the minimal bootstrap test seam needed for a no-private-plugin WordPress scenario and deterministic pinned scaffold selection.
- Record exact image/scaffolder/tool versions in reports; cache dependencies without caching generated secrets/state.

### Non-goals

- Do not exercise every framework/profile or service image on each pull request.
- Do not depend on user `.env`, SSH keys, private GitHub repositories, or production credentials.
- Do not conflate a skipped scenario with a pass.

## Dependencies and entry inputs

- Dependencies: `P02-C02`, `P03-C01`.
- Entry inputs: active spec, repository baseline, current helpers/tests/READMEs, and all completed dependency outputs.
- Capabilities: Bash, Python 3, Node where already required; runtime contracts additionally require rootless Podman and its configured Compose provider.

## Expected files/outputs

- `scripts/devarch/golden/*.yml or equivalent checked-in scenario definitions`
- `scripts/devarch/golden/*.sh thin probes where declarative checks are insufficient`
- `minimal targeted bootstrap changes/tests`
- `scripts/devarch/tests/golden_paths_test.sh`
- `README.md and component README updates`

## Specialist decisions incorporated

- TDD: scenario-by-scenario external-boundary Red ordering and cleanup-failure tests.
- Security: no user `.env`, SSH key, private plugin, or production secret dependency.
- Operations: pinned representative choices, injected-failure coverage, sequential repeat, and isolation canary.
- Performance: cache only immutable dependencies; bound pull/scaffold/readiness time.

## Acceptance criteria

1. All four named scenarios pass from a clean checkout on the supported runner and fail when their HTTP/database/routing assertion is deliberately broken.
2. Each scenario has a hard timeout, reports first failure within five minutes, and passes post-run leak detection.
3. Repeated sequential runs are idempotent; two isolation-canary runs do not collide where parallel execution is enabled.
4. Logs and artifacts contain no fixture secret values.

## Verification

- Red one scenario at a time: absent external assertion, then cleanup-on-failure; implement WordPress, Laravel, JavaScript, then composite path.
- Focused scenario run twice, injected-failure run, leak query, and report-schema/redaction assertion.
- Final `verify --scope golden` from a clean checkout on the supported runner.

## Rollback / migration constraints

Disable individual scenario registry entries first; revert minimal bootstrap seams independently; runtime harness and local direct workflows remain.
