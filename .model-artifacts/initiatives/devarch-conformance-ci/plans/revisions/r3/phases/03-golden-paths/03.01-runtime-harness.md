## Goal

Provide reusable runtime orchestration that isolates resources, proves readiness, captures bounded evidence, and always cleans up.

## Observable behavior

- Each run derives a collision-resistant ID and labels every created project/container/volume/network/temp path for ownership.
- The harness executes setup, bounded readiness probes, assertions, and teardown; traps cover normal exit, assertion failure, signal, and timeout.
- Post-teardown leak detection fails if any run-labelled resource or generated application remains.

## Scope and non-goals

### Scope

- Add runtime harness helpers and fake-runtime tests.
- Support HTTP with explicit `Host`, database command probes, container health/status, bounded logs, and JSON result events.
- Add preflight capability checks for rootless Podman, Compose provider, free resources, writable apps/temp locations, and outbound dependency needs.

### Non-goals

- Do not implement the four scenario bodies here.
- Do not edit `/etc/hosts`, use privileged containers, mount the container socket into applications, or prune resources not owned by the run.
- Do not parallelize scenarios sharing legacy fixed resources until isolation is proven.

## Dependencies and entry inputs

- Dependencies: `P01-C01`, `P02-C01`.
- Entry inputs: active spec, repository baseline, current helpers/tests/READMEs, and all completed dependency outputs.
- Capabilities: Bash, Python 3, Node where already required; runtime contracts additionally require rootless Podman and its configured Compose provider.

## Expected files/outputs

- `scripts/devarch/lib/runtime-verification.sh`

- `scripts/devarch/README.md`

## Specialist decisions incorporated

- Operations: label-owned cleanup, unique namespaces, bounded readiness, explicit capability failure, idempotent teardown, and post-run leak gate.
- Security: rootless only, no hosts mutation/privilege/socket mount, sanitized environment and redacted bounded logs.
- Performance: scenario/global time budgets and no unsafe parallelism.
- Compatibility: respect existing Podman/Compose-provider contracts.

## Acceptance criteria

1. Fake-runtime tests prove unique naming, label ownership, bounded polling, timeout, signal/failure cleanup, redaction, and leak failure.
2. Cleanup is idempotent and refuses to delete unlabeled/non-owned resources.
3. Skipped/unavailable capability is distinct from pass; required CI capabilities fail closed.
4. Runtime events conform to the P01 report schema.

## Verification

- Red order: leaked-resource failure, failed-assertion cleanup, signal cleanup, timeout, redaction, then successful lifecycle.
- Use fake Podman/Compose/curl/database commands first; run one disposable real-container canary only after green.
- Rerun unified static/unit scopes and inspect post-run owned-resource query.

## Rollback / migration constraints

Remove runtime helpers and golden scope wiring; static/unit verification remains available.
