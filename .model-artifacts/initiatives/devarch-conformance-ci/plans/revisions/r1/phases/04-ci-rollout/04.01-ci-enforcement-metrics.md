## Goal

Make verification an enforced, diagnosable CI contract and publish honest reliability measurements and operator guidance.

## Observable behavior

- Pinned CI workflows run static/unit and the four golden scenarios for pull requests and default-branch pushes, with path filters only if a test proves all dependency paths are covered.
- Jobs use least permissions, immutable action pins, concurrency cancellation, bounded timeouts/artifacts, and unconditional teardown.
- A summary reports per-check status, first failure, time-to-actionable-report, cleanup result, and rolling clean-run success; fewer than 30 samples reports `insufficient-sample`.

## Scope and non-goals

### Scope

- Add GitHub Actions workflows, runner setup, cache policy, artifact retention, and CI fixture generation.
- Document required check names, ownership, local reproduction, incident handling, exception review, rollback, and the manual branch-protection step.
- Add tests/lint for workflow references, immutable pins, permission scopes, registry coverage, and required teardown.

### Non-goals

- Do not automate repository administration or weaken fork security to expose secrets.
- Do not claim 99% reliability before 30 completed runs.
- Do not retain unbounded container logs or generated application trees.

## Acceptance criteria

1. Every pull request/default-branch push runs required static/unit and golden checks; relevant failures block merge after a maintainer enables documented branch protection.
2. Workflow permissions are read-only by default, actions are SHA-pinned, no production secret is required, and fork behavior is safe.
3. Artifacts are redacted, size/retention-bounded, and produced even on failure; teardown runs unconditionally and leak checks gate success.
4. The reliability summary computes a rolling 30-run success rate and median failure-to-report time; sparse samples are labelled honestly.
5. Documentation enables local reproduction and exact rollback, and existing direct commands remain supported.

## Verification

- Red: workflow/registry test fails before workflow exists; pin/permissions/teardown/path-coverage/sparse-metric tests.
- Run a pull-request-equivalent workflow locally where feasible and one actual CI run before requesting required-check activation.
- Inject one failure per layer, prove artifact timing/redaction/cleanup, then observe 30 completed default-branch/scheduled runs before asserting ≥99%.

## Rollback / migration constraints

Remove required-check setting manually first, disable workflow triggers, then revert workflow files; local verifier and metadata remain usable.
