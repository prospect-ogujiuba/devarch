## Goal

Define a versioned per-service conformance contract and a fail-closed validator for catalog structure and resolved Compose configuration.

## Observable behavior

- The validator enumerates canonical catalog IDs using existing catalog helpers and requires exactly one local `conformance.yml` per Compose service directory.
- Metadata and resolved Compose are cross-checked for canonical ID, declared service names, image/build source, variable names, published ports, volumes, networks, readiness/smoke tier, timeout, and exceptions.
- Resolution uses non-secret fixture values with `podman compose -f ... config --quiet`; diagnostics name variable keys but never values.

## Scope and non-goals

### Scope

- Specify schema version 1 and JSON-schema-equivalent validation rules in repository code/tests.
- Add validator/check implementation reusable by the unified `static` scope.
- Define explicit exception shape with rule, rationale, owner, and review-by date; expired or unknown exceptions fail.

### Non-goals

- Do not add metadata to all 170 directories here.
- Do not require a health check for structurally one-shot jobs; require explicit justified classification instead.
- Do not contact registries or start containers.

## Dependencies and entry inputs

- Dependencies: `P01-C01`.
- Entry inputs: active spec, repository baseline, current helpers/tests/READMEs, and all completed dependency outputs.
- Capabilities: Bash, Python 3, Node where already required; runtime contracts additionally require rootless Podman and its configured Compose provider.

## Expected files/outputs

- `scripts/devarch/lib/conformance.sh and/or a small dependency-free Python validator`
- `scripts/devarch/tests/conformance_test.sh or test_conformance.py`
- `scripts/devarch/conformance.schema.json (if JSON Schema is selected)`
- `README.md and scripts/devarch/README.md`

## Specialist decisions incorporated

Specialist review pending for TDD, security, migration, performance, operations, and compatibility.

## Acceptance criteria

1. Malformed, absent, duplicate, path-mismatched, extra-field, expired-exception, unknown-service, and secret-bearing fixtures fail with bounded path-specific diagnostics.
2. Valid service/job/aggregate-stack fixtures pass and resolved Compose service names match metadata.
3. All variable fixtures are generated placeholders; reports list keys only.
4. The validator integrates into `verify --scope static` without requiring running containers.

## Verification

- Red order: missing metadata, path mismatch, secret-bearing value, resolved-service mismatch, exception expiry, then valid fixtures.
- Run focused validator tests with fake Compose capability, then real `podman compose config` against bounded fixtures when available.
- Run the P01 verification suite to prove result-contract compatibility.

## Rollback / migration constraints

Remove schema/validator registration; no service Compose file or runtime behavior changes.
