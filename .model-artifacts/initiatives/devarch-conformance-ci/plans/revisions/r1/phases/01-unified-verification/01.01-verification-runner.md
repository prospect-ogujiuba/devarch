## Goal

Add a single repository-owned verifier that aggregates all existing static/unit checks and writes one stable, secret-safe result.

## Observable behavior

- `scripts/devarch/verify.sh --scope static|unit|all` discovers the repository physically, runs a canonical checked-in registry in deterministic order, and exits nonzero if any required check fails.
- Human output is concise; a versioned JSON report records check ID, command label (not secret-bearing argv), scope, start/end/duration, result, bounded diagnostic, and artifact paths.
- Registry-completeness tests fail when a recognized first-party test file is not registered or a registered file is missing.

## Scope and non-goals

### Scope

- Add `scripts/devarch/verify.sh`, focused libraries under `scripts/devarch/lib/`, a checked-in test registry, and tests under `scripts/devarch/tests/`.
- Register Compose/YAML shape, shell syntax, DevArch foundation, dashboard, hosts, JavaScript, Laravel, Node, WordPress, and router checks that are deterministic and non-runtime.
- Update the top-level development-check documentation to call the unified verifier while retaining direct commands in component READMEs.

### Non-goals

- Do not execute real containers in this contract.
- Do not remove or rename existing test entry points.
- Do not stream unlimited child output into the final report.

## Dependencies and entry inputs

- Dependencies: none.
- Entry inputs: active spec, repository baseline, current helpers/tests/READMEs, and all completed dependency outputs.
- Capabilities: Bash, Python 3, Node where already required; runtime contracts additionally require rootless Podman and its configured Compose provider.

## Expected files/outputs

- `scripts/devarch/verify.sh`
- `scripts/devarch/lib/verification.sh`
- `scripts/devarch/checks.yml (or an equivalently explicit registry)`
- `scripts/devarch/tests/verification_test.sh`
- `scripts/devarch/tests/run-tests.sh`
- `README.md and affected scripts/*/README.md`

## Acceptance criteria

1. One invocation runs the complete registered non-runtime suite and returns the first failing status only after recording all required results.
2. Output ordering, exit codes, interruption behavior, and JSON schema are deterministic and tested.
3. Discovery-vs-registry drift, duplicate IDs, invalid scopes, missing commands, timeout, and failing-child cases are covered.
4. Report redaction tests prove fixture secrets and environment values never appear.
5. All previously documented direct checks remain green.
