## Residual risks, migration, and scope boundaries

- The shared Bash dotenv grammar is intentionally bounded; broader dotenv compatibility requires a new plan.
- External wrappers that relied on unsafe arbitrary `set -a` export will observe the intentional security tightening.
- Existing MariaDB volumes still require the password used at initialization; changing the local file does not rotate it.
- Container-runtime execution was intentionally excluded because Compose/service behavior did not change; host-only fake-runtime coverage matches the approved scope.
- No local `.env`, volume, database, generated application configuration, Compose design, service credentials, or unrelated service-catalog defaults were migrated or changed.
- Rollback is source-only: restore the prior scripts, tests, template, and documentation. No persistent-data rollback is required.
