# MakerDesk spreadsheet alignment phase index

Created: 2026-08-23
Purpose: Sequence a scaffold-first, auditable expansion of MakerDesk using `IT_Management_System.xlsm` as the minimum feature contract.

## Outcome

Retain MakerDesk's existing portal, WordPress users/capabilities, workflow, optimistic locking, immutable ticket activity, SLA, notification, reporting, and form conventions while adding complete support for spreadsheet Tickets, Employees, Printers, Provisions, record forms, archive behavior, and controlled lookup values.

## Guardrails

- Scaffold new vertical resources with `galaxy_playground_app make:maker-resource ... --migration --views --factory --tests --no-interaction` before customization.
- Use TypeRocket/Galaxy generators for controllers, services, jobs, commands, and migrations where available.
- Keep business records linked to WordPress users without assuming every employee must have a login.
- Keep audit actor IDs distinct from subject/owner user IDs.
- Prefer first-class relational columns for operational data; JSON only for optional integrations.
- Migrations are additive and rollback-aware; take a database backup before applying.
- Do not collapse existing robust ITSM capabilities to spreadsheet-only behavior.

## Phases

1. `01-schema-map-and-scaffold.md` — freeze field mapping and generate resource skeletons.
2. `02-people-directory.md` — employees, departments, and WordPress identity linkage.
3. `03-assets-printers-provisions.md` — inventory, printer operations, assignment/provision history.
4. `04-ticket-work-management.md` — spreadsheet planning/hierarchy/effort fields within existing ITSM workflow.
5. `05-forms-import-reports.md` — operational forms, workbook migration command, filters, dashboards, exports.
6. `06-audit-security-verification.md` — cross-domain audit, policy hardening, migration and contract verification.
7. `07-scaffold-retrospective.md` — only after implementation, capture repetitive work and propose/update generator commands/templates.

## Implementation order

Implement one phase at a time. Each phase must pass its verification gate before the next schema-dependent phase. Phase 07 is deliberately last.

## Global definition of done

- All spreadsheet columns and controlled lists are represented or mapped to a stronger equivalent.
- Employee, requester, assignee, asset owner, provision recipient, and audit actor relationships are unambiguous.
- Historical assignments and audit events remain queryable after reassignment/deactivation.
- Forms and lists support day-to-day IT operations without exposing raw IDs or JSON for common fields.
- Existing MakerDesk contracts remain green and new contracts cover every new resource/workflow.
- A final scaffold-friction report recommends concrete automation based on observed repetition.
